# Leave Management API

A Spring Boot REST API that lets employees submit and manage leave requests for an organization's HR system.
Data is held in memory (`ConcurrentHashMap`).

## Project overview

| Package | Responsibility |
|---------|----------------|
| `controller` | REST endpoints (`LeaveController`) |
| `service` | Business rules and DTO/model mapping (`LeaveService`) |
| `repository` | `LeaveRepositoryInterface` interface + `LeaveRepository` |
| `model` | `LeaveRequest`, `LeaveType`, `LeaveStatus` |
| `dto` | `LeaveRequestDto` (input), `LeaveResponse` (output), `ErrorResponse` |
| `exception` | Custom exceptions and `ExceptionHandler` (`@RestControllerAdvice`) |
| `configuration` | `AppConfig` (Clock bean), `LeaveProperties` (typed config), `DataLoader` (dev-only seed data) |

Key practices: constructor-based dependency injection, DTOs at the API boundary, Bean Validation on requests,
centralised exception handling, externalised configuration and Spring profiles.

## Build and run

Prerequisite: a JDK matching the toolchain in `build.gradle` (Java 27). Gradle can download the toolchain
automatically if it is configured for it.

```bash
# build and run all tests
./gradlew clean build

# start the application on http://localhost:8080
./gradlew bootRun
```

If the project has no Gradle wrapper, use a locally installed `gradle` instead of `./gradlew`.

### Profiles

| Profile | How it behaves |
|---------|----------------|
| `dev` (default) | Debug logging, max leave duration 60 days, two sample leave requests are seeded at startup |
| `prod` | Quiet logging, max leave duration 30 days, no seed data |

```bash
# run with the prod profile
SPRING_PROFILES_ACTIVE=prod ./gradlew bootRun
# or
./gradlew bootRun --args='--spring.profiles.active=prod'
```

### Configuration (`application.yaml`)

| Property | Default | Meaning |
|----------|---------|---------|
| `server.port` | `8080` | HTTP port |
| `leave.max-duration-days` | `30` | Longest leave (inclusive days) a single request may span |

## API summary

Base path: `/leaves`

| Method | Endpoint | Description | Success |
|--------|----------|-------------|---------|
| GET | `/leaves` | Retrieve all leave requests | 200 |
| GET | `/leaves/{id}` | Retrieve a leave request by ID | 200 |
| POST | `/leaves` | Create a new leave request | 201 + `Location` header |
| PUT | `/leaves/{id}` | Update an existing leave request | 200 |
| DELETE | `/leaves/{id}` | Delete a leave request | 204 |

### Leave request fields

| Field | Type | Rules |
|-------|------|-------|
| `id` | number | Generated by the server (response only) |
| `employeeId` | string | Required, not blank, max 50 chars |
| `leaveType` | enum | Required: `ANNUAL`, `SICK`, `CASUAL`, `UNPAID` |
| `startDate` | date `yyyy-MM-dd` | Required; not in the past on create |
| `endDate` | date `yyyy-MM-dd` | Required; must not be before `startDate` |
| `reason` | string | Required, not blank, max 500 chars |
| `status` | enum | `PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`. Optional in the request: new requests are always `PENDING`; on `PUT`, omitting it keeps the current status |

The duration (`startDate` to `endDate`, inclusive) must not exceed `leave.max-duration-days`.

### Error format

All errors share one JSON shape:

```json
{
  "timestamp": "2026-11-19T10:15:30.123Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "path": "/leaves",
  "details": ["employeeId: employeeId must not be blank"]
}
```

| Status | When |
|--------|------|
| 400 | Validation failure, malformed JSON, invalid enum/date value, business-rule violation |
| 404 | Leave request not found |
| 405 / 415 | Unsupported method / media type (standard Spring behaviour) |
| 500 | Unexpected error |
